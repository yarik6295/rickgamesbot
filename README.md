# 🎮 Bulkster Games — Telegram Mini App (демо-версия)

Прототип для портфолио: кейсы, инвентарь и 4 казино-стиль игры
(Crash / Mines / Towers / Plinko) на **полностью виртуальном балансе**.
Тёмный неоновый UI. Backend на Node.js/Express + SQLite, вся генерация
результатов и вся ставочная логика — **на сервере**.

## ⚠️ Важно: про валюту в проекте

Баланс (`coins_balance`) — это демонстрационные монеты:

- **нельзя купить за реальные деньги** — единственный способ пополнения:
  `POST /api/user/daily-bonus` (фиксированная сумма раз в 24 часа);
- **нельзя вывести** ни в деньги, ни в подарки — предметы из кейсов чисто
  коллекционные и продаются только обратно за монеты.

Это сделано намеренно: проект — рабочая демонстрация игровых механик
(server-side RNG, provably-fair подход, честная математика мультипликаторов)
без денежного контура. Если решите продолжать этот проект в сторону реальных
платежей, учтите, что приём денег под ставки в играх со случайным исходом
почти везде подпадает под регулирование азартных игр и требует лицензии —
это находится вне того, что можно правомерно эксплуатировать без неё.

## Игры

Вся генерация результата — **только на сервере** (`crypto.randomInt`/`crypto.randomBytes`),
клиент лишь отправляет действия и анимирует уже готовый ответ. Каждый раунд
логируется в `game_rounds` (тип игры, ставка, выплата, мультипликатор, seed) —
это тот же provably-fair подход, что и в аудит-логе открытия кейсов.

- **Crash** — общий непрерывный раунд **для всех игроков одновременно**
  (как в реальных crash-казино), а не отдельный раунд на пользователя.
  Раунд крутится в памяти сервера сам по себе, с момента старта процесса, по
  циклу `waiting` (6с, приём ставок) → `flying` (мультипликатор растёт по
  `e^(0.11·t)`) → `crashed` (3.5с, показ результата) → снова `waiting`.
  `GET /games/crash/state` отдаёт текущую фазу/мультипликатор/историю
  последних раундов/число игроков — один и тот же ответ для всех, кто
  спросит в этот момент. `POST /games/crash/bet` — присоединиться к раунду
  во время приёма ставок, `POST /games/crash/cashout` — забрать выигрыш до
  краша. Клиент поллит `state` (~400мс) и досчитывает мультипликатор
  локально между опросами (requestAnimationFrame по той же формуле) для
  плавной анимации — но решает всё сервер. Логика раунда — в
  `backend/src/services/crashEngine.js`.
- **Mines** — сетка 5×5, `POST /games/mines/start` (ставка + кол-во мин),
  `POST /games/mines/reveal` открывает клетку, `POST /games/mines/cashout`
  фиксирует текущий мультипликатор. Позиции мин хранятся в `active_rounds`,
  не отдаются клиенту до конца раунда.
- **Towers** — 8 этажей × 3 плитки (1 бомба на этаж), логика аналогична Mines.
- **Plinko** — мгновенный раунд: `POST /games/plinko/play` (ставка + риск
  low/medium/high) считает путь шарика криптографическим RNG и мультипликатор
  по таблице корзин.
- **Upgrade** (апгрейдер, как в CS-кейс-сайтах) — `POST /games/upgrade/play`.
  Игрок сам выбирает шанс выигрыша (2–90%), сервер считает множитель как
  `(100/шанс) × 0.92` (8% house edge) и делает один ролл 1..100. Ставить можно
  монетами (выигрыш = монеты × множитель) **или предметом из инвентаря**
  (при выигрыше предмет заменяется новым, более дорогим — генерируется в
  скрытый служебный кейс `upgrade_rewards`, при проигрыше сгорает).
- **Wheel** (колесо удачи) — `POST /games/wheel/play`. Одна ставка — одно
  вращение, сервер выбирает сектор взвешенным RNG (10 секторов, от ×0 до
  ×20, RTP ≈ 95%) и отдаёт готовый результат, клиент просто анимирует поворот
  колеса на нужный угол.

Оба предмета/выигрыши из Upgrade и обычных кейсов — **чисто коллекционные**:
лежат в инвентаре как достижение, продаются только за монеты (см. раздел про
валюту выше), никакого реального вывода нет.

## Запуск

```bash
cd backend
cp .env.example .env      # для локального теста поставьте DEV_SKIP_TELEGRAM_AUTH=true
npm install
npm run seed               # наполнить кейсы тестовыми данными
npm start                  # http://localhost:3000
```

Фронтенд раздаётся тем же Express-процессом статикой из `frontend/`.
В проде `DEV_SKIP_TELEGRAM_AUTH` должен быть `false`, а `BOT_TOKEN` — задан,
чтобы валидировался реальный Telegram WebApp `initData`.
